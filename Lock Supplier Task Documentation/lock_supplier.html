Code-Level Disablement of NDC Supplier & Credentials

Technical Investigation & Implementation Approaches

Overview

This document outlines the investigation and technical approach for implementing code-level disablement of suppliers and their related customers in the NDC system.

Primary Goal: Establish a mechanism that ensures system-enforced distribution and prevents unauthorized manipulation of supplier settings.

Objectives

  • Disables suppliers and credentials directly at code level — ensuring system-enforced distribution
  • Prompts U-Board modifications — business units cannot re-make or modify board suppliers through the admin interface
  • Provides premium distributions carried — specific suppliers requiring system-enforced distribution remain protected
  • Prevents unauthorized manipulation — accidents or intentional restrictions on the U-B Boarded suppliers

Approach 3: Enum-Based Locking

Add an enum containing all locked suppliers to enforce disablement at the configuration level.

Implementation Details
  • Enum Definition
    • Add a LockedSupplier enum with all locked suppliers
  • Validation Logic
    • Check whether the supplierConfigModal has a locked supplier from this enum
    • If having, remove this from the supplierConfigModal list

Approach 4: Code-Level Flag

Add a boolean flag to the required supplier to enforce disablement directly in the code.

Implementation Details
  • Flag Implementation
    • Add a boolean flag to the required supplier
  • Validation Logic
    • Check for this boolean flag if it's true, lock this supplier
    • So the user cannot activate it

Conclusion

Both approaches provide robust mechanisms for achieving supplier disablement at the code level. The Global Solution Flow Question set:

  • Security requirements — Approach 2 offers stronger protection
  • Protecting vessels — Approach 1 allows easier business logic considerations
  • System architecture — Connects existing systems in the codebase
Recommendation: A hybrid approach combining both service layer validation and database triggers may provide the optimal balance of flexibility and security.
